## 1. Tiếp tục hoàn thiện màn Báo giá

Tiếp tục hoàn thiện toàn bộ flow báo giá theo các nghiệp vụ đã thống nhất trước đó, bao gồm:

- Báo giá theo **Danh mục sản phẩm (Category)**.
- Giá tham chiếu theo thứ tự:
  1. Báo giá gần nhất có cùng `Customer + Category`.
  2. Nếu không có, lấy báo giá gần nhất của `Category` bất kể khách hàng.
  3. Nếu Category chưa từng được báo giá, sử dụng dữ liệu mặc định từ Category:
     - Đơn vị tính.
     - Giá nhập tham chiếu.
     - Giá bán mặc định.
     - Có VAT hay không.
     - % VAT.
- Mỗi dòng Category trong báo giá có:
  - Hàng hóa đề xuất.
  - Hàng hóa cung cấp.
  - Quy cách/Nhãn hiệu.
  - Đơn vị.
  - Số lượng.
  - Đơn giá.
  - VAT.
  - Thành tiền.
  - **Ghi chú riêng của từng dòng**.

## 3. Rà soát panel/menu chức năng của toàn hệ thống

Cần rà soát lại **panel chức năng chính / sidebar navigation của toàn hệ thống** để xác định những chức năng hiện tại không còn sử dụng, không thuộc scope nghiệp vụ thực tế hoặc đã được thay thế bởi flow mới.

Mục tiêu là:

> Chỉ hiển thị những chức năng mà hệ thống hiện đang thực sự sử dụng, tránh để menu thừa gây rối cho người dùng.

### 3.1. Rà soát toàn bộ menu hiện có

Kiểm tra từng menu/module như:

```text
Dashboard
Danh mục
Sản phẩm
Kho
Nhập kho
Nhà cung cấp
Khách hàng
Báo giá
Đơn hàng
Giao hàng
Ledger / Lịch sử kho
Demo nghiệp vụ
...
```

Với từng chức năng cần xác định:

```text
1. Có còn được sử dụng không?
2. Có nằm trong nghiệp vụ hiện tại không?
3. Có màn hình/API thực sự hoạt động không?
4. Có bị trùng chức năng với module khác không?
5. Có phải chức năng cũ đã được thay thế không?
```

### 3.2. Chức năng không sử dụng thì ẩn

Nếu một chức năng:

- Chưa sử dụng.
- Chưa hoàn thiện.
- Không còn phù hợp với nghiệp vụ mới.
- Chỉ là màn demo cũ.
- Bị trùng với chức năng khác.

thì **ẩn khỏi panel/menu**.

Không bắt buộc phải xóa code hoặc API ngay.

Ví dụ:

```text
feature còn code
        ↓
sidebar không hiển thị
        ↓
route có thể disable hoặc permission deny
```

Như vậy nếu sau này cần dùng lại vẫn có thể bật lại.

### 3.3. Nên sử dụng Feature Configuration

Không nên hard-code từng menu kiểu:

```text
display: none
```

Nên có config như:

```text
features:
  dashboard: true
  categories: true
  products: true
  warehouses: true
  quotations: true
  demo: true

  oldOrderModule: false
  oldImportModule: false
```

Sidebar render dựa theo feature configuration.

Như vậy có thể:

- Bật/tắt chức năng nhanh.
- Không cần sửa component menu mỗi lần.
- Dễ triển khai khác nhau giữa Demo / Production.
- Có thể kết hợp permission sau này.

### 3.4. Phân biệt Feature Flag và Permission

Cần tách:

```text
Feature enabled?
        +
User có permission?
        ↓
Hiển thị menu
```

Ví dụ:

```text

```

có thể:

```text
feature.demo = true
```

nhưng chỉ:

```text

```

mới nhìn thấy.

Trong khi:

```text
Báo giá
```

có thể cho:

```text
Admin
Sales
```

sử dụng.

### 3.5. Menu ẩn thì route cũng cần được bảo vệ

Không được chỉ ẩn menu FE nhưng người dùng vẫn truy cập được bằng URL trực tiếp.

Ví dụ menu:

```text
/old-feature
```

đã bị disable thì truy cập URL trực tiếp cũng phải:

```text

```

hoặc:

```text

```

tùy thiết kế.

Backend API liên quan cũng cần kiểm tra permission/feature nếu chức năng thực sự bị disable.

### 3.6. Kết quả mong muốn

Sau khi rà soát, sidebar chỉ còn các chức năng cần thiết cho flow chính, ví dụ:


Danh sách cuối cùng cần dựa trên **các chức năng thực tế hiện có trong code**, không mặc định dùng đúng ví dụ trên.

## 4. Panel tham chiếu Báo giá – giới hạn dữ liệu hiển thị

Phần này là **panel Reference nằm trong màn Báo giá**, khác với panel/menu chức năng hệ thống ở mục 3.

Các tab/khung reference như:

- `Cùng khách`
- `Gần đây`
- `Giá nhập`

không được load toàn bộ dữ liệu ngay từ đầu.

### Initial load

Mỗi section chỉ hiển thị khoảng:

```text
3–5 records
```

Đề xuất mặc định:

```text
pageSize = 5
```

### Lazy loading

Khi user scroll gần cuối danh sách:

```text
offset += 5
```

và request tiếp.

Ví dụ:

```http
GET /api/quotation-reference/same-customer
?categoryId=...
&customerId=...
&limit=5
&offset=0
```

Scroll:

```http
GET ...
&limit=5
&offset=5
```

Tiếp:

```text
offset = 10
offset = 15
...
```

Cho đến khi:

```text
loaded >= total
```

thì dừng.

Không request tiếp nếu API đã hết dữ liệu.

## 5. Chuẩn hóa logic `Cùng khách`

Hiện tại API có trả `count > 0` nhưng UI không hiển thị dữ liệu nên cần kiểm tra lại FE mapping và điều kiện render.

Logic chuẩn của tab `Cùng khách` phải là:

```text
Selected Customer
        +
Selected Category
        ↓
QuotationItem có:
CustomerId = selectedCustomerId
AND
CategoryId = selectedCategoryId
```

Chỉ lấy các báo giá hợp lệ.

Không lấy:

```text
Deleted
Cancelled
```

Có thể ưu tiên các trạng thái:

```text
ACCEPTED
CONVERTED
AWAITING_DELIVERY
DELIVERED
```

sau đó mới tới các trạng thái báo giá hợp lệ khác.

Sort:

```text
quotationDate DESC
createdAt DESC
```

Kết quả hiển thị:

```text
Product/Category
Customer
Quantity
Sale Price
Reference Purchase Price
VAT
Margin
QuotationLabel
Quotation Date
```

Ví dụ:

```text
Ống kẽm Hòa Phát
Công ty ABC
SL: 20

Giá nhập ref: 112.000
Giá bán:      148.000
VAT:          8%

H2T-14092026-2
12/09/2026
```

### Cần kiểm tra lỗi UI hiện tại

Nếu API trả:

```text
total > 0
```

nhưng tab không hiển thị thì cần kiểm tra ít nhất:

- FE đang đọc `data.items` hay một property khác.
- `total/count` và `items` có cùng level hay không.
- Tab có filter lại `customerId/categoryId` một lần nữa ở FE khiến toàn bộ item bị loại hay không.
- `customerId` là string/UUID nhưng FE đang compare với object.
- `categoryId` nằm trong `quotationItem` nhưng FE lại đọc từ root.
- Query key cache của React Query có thiếu `customerId` hoặc `categoryId`.
- Khi đổi tab, data có bị reset trước khi render không.
- Infinite query đang đọc sai `pages[].items`.
- Điều kiện kiểu:

```text
total > 0 && items.length === 0
```

đang rơi vào empty state sai.
- API đang trả page đầu ở field khác so với API pagination cũ.

FE **không được dựa vào `total > 0` để render card**.

Phải render dựa vào:

```text
items.length > 0
```

`total` chỉ dùng cho pagination/lazy loading.

## 7. Primary Reference tự động

Ngoài hai danh sách trên, hệ thống vẫn cần xác định một `Primary Reference`.

Rule:

```text
Có quotation cùng Customer + Category?
              │
             YES
              ↓
Lấy record gần nhất
              │
              └── CUSTOMER_CATEGORY_QUOTATION

             NO
              ↓
Có quotation nào của Category?
              │
             YES
              ↓
Lấy record gần nhất
              │
              └── CATEGORY_QUOTATION

             NO
              ↓
Lấy default Category
              │
              └── CATEGORY_DEFAULT
```

Primary Reference dùng để gợi ý:

- Unit.
- Giá nhập tham chiếu.
- Giá bán.
- VAT.

Còn `Cùng khách / Gần đây / Giá nhập` là danh sách để user xem thêm và có thể chọn reference khác.

## 8. Pagination/Lazy loading cho toàn bộ Master Data

Không load toàn bộ dữ liệu master ngay khi mở màn hình.

Áp dụng cho:

- Category.
- Customer.
- Supplier.
- Warehouse.
- Product.
- Unit.
- Các dropdown master khác.

Default:

```text
limit = 20
offset = 0
```

Khi scroll gần cuối dropdown:

```text
offset += 20
```

API:

```http
GET /api/lookups/categories
?search=...
&limit=20
&offset=0
```

Response thống nhất:

```json
{
  "items": [],
  "total": 153,
  "limit": 20,
  "offset": 0
}
```

Dropdown search phải reset:

```text
offset = 0
items = []
```

sau đó query lại theo keyword.

Không được search trên 20 item hiện đang có ở FE rồi coi đó là toàn bộ dữ liệu.

## 11. Quy tắc `quotationLabel`

Format:

```text
H2T-ddMMyyyy-sequence
```

Ví dụ ngày:

```text
14/09/2026
```

Các quotation lần lượt:

```text
H2T-14092026-1
H2T-14092026-2
H2T-14092026-3
```

Ngày tiếp theo:

```text
H2T-15092026-1
```

Sequence reset theo ngày.

### Logic

```text
prefix =
"H2T-" + format(currentDate, "ddMMyyyy") + "-"

maxSequence =
MAX(sequence)
WHERE quotationDate = currentDate

nextSequence =
maxSequence + 1

quotationLabel =
prefix + nextSequence
```

### Lưu ý concurrency

Không nên chỉ:

```text
SELECT MAX + 1
INSERT
```

mà không có transaction.

Nếu 2 user tạo cùng lúc:

```text
User A → MAX = 5
User B → MAX = 5
```

cả hai có thể tạo:

```text
H2T-14092026-6
```

Do đó cần:

- Unique index trên `quotationLabel`.
- Sinh sequence trong transaction.
- Lock phù hợp hoặc retry nếu conflict.

Ví dụ:

```text
UNIQUE(quotationLabel)
```

Nếu insert bị duplicate:

```text
recalculate next sequence
retry
```

## 13. Filter màn List theo quotationLabel

Search/filter hiện tại cần bổ sung:

```text
quotationLabel
```

Ví dụ user search:

```text
H2T-14092026
```

thì trả toàn bộ báo giá ngày đó.

Search:

```text
H2T-14092026-3
```

trả quotation cụ thể.

Backend search có thể áp dụng:

```text
quotationLabel ILIKE '%keyword%'
```

Nếu search chung qua `keyword` thì có thể tìm trên:

```text
quotationLabel
OR customerName
OR projectName
...
```

tùy các field hiện tại của màn list.

## 15. Acceptance Criteria chính

### Panel/menu chức năng hệ thống

- Rà soát toàn bộ menu hiện có.
- Chức năng không sử dụng được ẩn.
- Chức năng chưa hoàn thiện có thể disable/ẩn.
- Không xóa code chỉ vì menu bị ẩn.
- Feature flag quyết định module có được bật hay không.
- Permission quyết định user có được nhìn/thao tác hay không.
- Menu bị ẩn thì route/API tương ứng vẫn phải được bảo vệ.
- Demo nghiệp vụ có thể bật/tắt độc lập.

### Reference Panel

- Chọn Customer + Category có lịch sử → `Cùng khách` có dữ liệu.
- Category có lịch sử → `Gần đây` có dữ liệu.
- `total > 0` và API trả items → UI bắt buộc render items.
- Initial load tối đa 5 item/tab.
- Scroll cuối → load tiếp.
- Hết dữ liệu → không request tiếp.
- Đổi Customer → reload `Cùng khách`.
- Đổi Category → reload cả `Cùng khách`, `Gần đây`, `Giá nhập`.

### Master Data

- Initial load 20.
- Infinite scroll load tiếp 20.
- Search reset pagination.
- Không load toàn bộ DB vào dropdown.

### Quotation Label

- Hiển thị `quotationLabel`, không hiển thị DB ID.
- Format đúng `H2T-ddMMyyyy-N`.
- Sequence tăng trong cùng ngày.
- Sang ngày mới reset về `1`.
- Không duplicate khi concurrent create.
- Update quotation không đổi label.
- Filter/search được bằng quotationLabel.

### PDF

- Layout bám template `BÁO GIÁ KIÊM XN ĐH.xlsx`.
- Bảng không lệch cột.
- Ghi chú từng Category được export.
- Có khoảng trắng hợp lý cho chữ ký.
- Preview và file xuất có nội dung thống nhất.

### Demo

- Có đủ scenario reference fallback.
- Category Demo có default price/unit/VAT.
- Full flow hoạt động với nghiệp vụ mới.
- Cleanup vẫn xóa hết `source = dataDemo`.
